## 3. Current source problem

Current Group Chat translation is recipient-scoped:

```text
GroupChatTranslation
  recipient_membership_id
  message_id
  target_language
  message_fingerprint
```

Therefore B and C with the same target language can create separate translation records/provider work for the same message version.

Current provider work is also requester-context based, which is directionally compatible with the new payer policy, but storage/reuse is not shared enough.

Target architecture:

```text
ONE message-version + target-language variant
-> shared by every authorized member
-> only created when a user actually requests/enables that translation
```

## 4. Canonical Group Chat identity

```text
(message_id, message_fingerprint, target_language)
```

`recipient_membership_id` must not be part of shared variant identity.

Message edit behavior:

```text
fingerprint F1 -> F2
old F1 variants remain historical/stale
must not be projected as current F2 translation
new F2 target variants are created only on demand
```

## 5. Cost ownership — first requester who creates missing shared variant

Canonical rule:

```text
COST_UNIT=NEW_UNIQUE_CHAT_TRANSLATION_VARIANT
COST_OWNER=FIRST_SUCCESSFUL_REQUESTER_WHO_CAUSES_MISSING_VARIANT_CREATION
EXISTING_FINAL_REUSE_COST=0
SAME_LANGUAGE_REUSE_COST=0
RECIPIENT_COUNT_MULTIPLIES_PROVIDER_COST=NO
```

The requester may be either sender or recipient.

Examples:

```text
A sends VI source message X
No translation requested
-> provider calls=0
-> A cost=0

B first requests X -> zh-TW
-> missing variant
-> provider call=1
-> COST_OWNER=B

C later needs zh-TW
-> reuse B-created FINAL variant
-> additional provider call=0
-> C cost=0

D first requests X -> en
-> provider call=1
-> COST_OWNER=D

E later needs en
-> reuse
-> additional provider call=0
-> E cost=0
```

If A explicitly requests an outgoing EN translation before D:

```text
A causes missing X/en creation
-> COST_OWNER=A
-> D,E later reuse at zero new provider cost
```

## 6. No room-wide automatic translation by language presence

Merely having members with different preferred languages in a room must not precompute translation variants.

Required:

```text
MESSAGE_CREATED
-> save authoritative source only
-> provider calls=0 unless a user has explicitly opted in/requested translation
```

Do not implement:

```text
message sent
-> scan all room languages
-> automatically create all missing target variants
```

That behavior is rejected for Group Chat because it creates provider work even when no user needs the translation.

## 7. Auto Translate semantics — explicit opt-in authorization

Per-user Auto Translate may exist, but it is opt-in.

For B:

```text
AUTO_TRANSLATE=ON
TARGET=zh-TW
```

When a new source message arrives:

```text
source == zh-TW
-> source reuse, cost=0

source != zh-TW
-> lookup shared X/F/zh-TW first
   -> FINAL exists: reuse, cost=0
   -> missing: B may become first successful requester/cost owner
```

If B and C both enable zh-TW Auto Translate:

```text
same message + same fingerprint + same target
-> provider calls=1
-> one successful reservation owner pays
-> other requester waits/reuses
-> double charge=NO
```

Auto Translate means the user authorizes missing provider work when required. It does not mean the user is charged when a reusable FINAL variant already exists.

## 8. Reuse before quota check

Required request order:

```text
1. authorize member/message access
2. determine source + target
3. target == source -> use source, cost=0
4. lookup shared FINAL variant
5. FINAL exists -> return immediately, provider call=0
6. only when missing -> acquire canonical reservation/lock
7. recheck FINAL after lock
8. only if still missing -> check/reserve requester quota
9. call provider once
10. persist shared FINAL variant
11. settle requester cost only on successful provider work
```

A user with no remaining new-translation quota must still be able to reuse an already-authorized FINAL shared variant because reuse creates no new provider cost.

## 9. Historical Group Chat behavior

History is source-first and on-demand.

Required:

```text
LOAD_SOURCE_HISTORY=YES
LATE_JOIN_HISTORY_AUTO_TRANSLATE=NO
LATE_JOIN_HISTORY_AUTO_READ=NO
HISTORY_TRANSLATE=ON_DEMAND
HISTORY_TTS=MANUAL_ON_DEMAND
```

For each historical message:

```text
recipient target == source
-> source usable, cost=0

shared FINAL target exists
-> reuse immediately
-> provider call=0
-> requester cost=0

shared target missing
-> show explicit Translate
-> user who causes first successful creation becomes COST_OWNER
```

Example:

```text
A authored X/vi three days ago
B already created/paid X/zh-TW
F joins later and uses zh-TW
-> reuse
-> F cost=0

G joins later and needs en
X/en missing
G presses Translate
-> provider call=1
-> COST_OWNER=G
-> later EN users reuse free of new provider cost
```

Manual historical Translate must not trigger Auto Read.
Historical Play is explicit local-device TTS only.

## 10. Concurrency / idempotency

Two users can request the same missing target simultaneously.

Required:

```text
message X + fingerprint F + zh-TW
B request ----\
              -> canonical lock/reservation
C request ----/         |
                       v
                ONE provider call
                ONE stored FINAL variant
```

Payer selection:

```text
FIRST_SUCCESSFUL_RESERVATION_OWNER=COST_OWNER
LOSING_REQUESTER_ADDITIONAL_COST=0
```

Database uniqueness alone is insufficient. The implementation must prevent duplicate provider calls before external provider invocation.

Use a stable provider idempotency key derived from:

```text
message_id + message_fingerprint + target_language
```

## 11. Provider failure / accounting

Do not permanently charge a requester simply because they pressed Translate.

Target flow:

```text
missing shared variant
-> requester quota eligibility
-> reserve bounded usage
-> provider call
-> success: settle approved/actual usage
-> failure: release/expire reservation; no settled translation charge
```

Exact commercial package units remain outside this migration unless already provided by an approved billing schema.
