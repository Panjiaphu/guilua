## 4. Root-cause targets confirmed/raised by Planner + Codex audit

Executor must confirm only the directly relevant current-source details before editing. Do not redo broad project archaeology.

### 4.1 Dropped realtime reconciliation

A translation/radio invalidation received while `state.busy` is true must not be permanently dropped.

Required behavior:

```text
EVENT RECEIVED
-> schedule/coalesce refresh intent
-> if temporarily busy, retain pending intent
-> execute promptly after busy clears
-> generation/space guards prevent stale refresh
```

No unbounded refresh loop.

### 4.2 Reconnect reconciliation

SSE/EventSource reconnect/open or temporary transport loss must trigger authoritative reconciliation of the current space's relevant translation/radio history. Do not depend on receiving every invalidation event exactly once.

A full durable `Last-Event-ID` replay implementation is optional only if the smaller authoritative reconciliation design fully closes the defect. Prefer the smallest reliable design.

### 4.3 PROCESSING -> terminal convergence

If a visible translation/radio segment remains PROCESSING after an event race, add a bounded reconciliation mechanism while unresolved segments exist. It must stop when:

- all visible pending segments reach terminal state;
- runtime/surface is disposed or changed;
- retry budget/time window is exhausted.

No permanent polling.

### 4.4 Auto Read dedupe timing

Do not permanently mark a FINAL segment as Auto-Read consumed before speech playback actually starts.

Required conceptual state:

```text
NEW
-> QUEUED
-> speech onstart => STARTED / consumed for this delivery
-> onend => COMPLETED
-> onerror before start => retry-eligible / explicit failure
```

Avoid duplicate speech while allowing recovery from a blocked or failed first attempt.

Additional confirmed audit cases that must be fixed:

- bootstrap/history load must not permanently mark existing eligible FINAL items as consumed merely because playback did not start;
- temporary `auto_read=false` or `media_connected=false` must not permanently consume an item that never played;
- multiple FINAL items arriving together must not all be marked consumed while only the first one speaks.

Required multi-item behavior:

```text
FINAL A + FINAL B + FINAL C
-> queue deterministically
-> A onstart/onend
-> B onstart/onend
-> C onstart/onend
-> no loss
-> no duplicate speech
```

### 4.5 Radio reconnect / media-connected race

The audit confirmed a specific race: a FINAL Radio translation can arrive while Radio is temporarily disconnected/reconnecting and `media_connected=false`. That state must not permanently consume/suppress Auto Read.

Required behavior:

```text
FINAL arrives while temporarily not media-connected
-> history remains authoritative
-> item remains playback-eligible
-> reconnect/reconciliation restores eligible playback
-> no permanent autoplaySeen-style suppression before actual onstart
```

Do not make Auto Read depend on a transient connection flag in a way that loses delivery permanently.

### 4.6 Shared TTS lifecycle

Manual Play and Auto Read must use one deterministic local TTS owner. A focused module such as `group_tts_manager.js` is allowed/preferred if it reduces duplicated state.

Minimum responsibilities:

- `speechSynthesis` capability detection;
- `getVoices()` readiness and `voiceschanged` handling;
- language-to-voice selection for `vi`, `en`, `zh-TW` when a matching local voice exists;
- one active playback owner and deterministic queue policy;
- `cancel`/`resume` recovery where supported;
- strong references to active utterance objects for the playback lifecycle;
- `onstart`, `onend`, `onerror` state;
- bounded start timeout / recoverable failure when `onstart` never arrives;
- explicit UI failure instead of silent no-op;
- user-gesture TTS test/unlock path from Device Settings.

Do not claim browser autoplay policy can be bypassed. On platforms requiring user interaction, enabling/testing TTS establishes the user-gesture readiness path and the UI must expose recovery clearly.

### 4.7 FINAL but missing recipient variant must be truthful

The audit found a valid additional invariant inside owner defect #5: a segment may be terminal while the recipient projection lacks translated text for the expected target language.

The UI must never show this contradictory state:

```text
segment.state=FINAL
translated_text=null
UI="Đang chờ bản dịch..."
```

Required result for an expected recipient target:

```text
EITHER
FINAL + translated_text present

OR
explicit terminal failure/missing-variant state
(e.g. FAILED / MISSING_VARIANT / equivalent existing contract)
```

Choose the smallest architecture-compatible fix. If target/profile changes can cause projection drift, make target/variant resolution deterministic for the burst/segment or return a truthful terminal state. Do not add a migration unless strictly required.

### 4.8 Shared per-device communication settings

Add a **Thiết bị giao tiếp / Communication devices** section to the unified `Dịch Chat` / Translation surface. It is shared by Group Video and Radio on the same browser/device.

Expected controls when supported:

```text
Microphone
Camera
Speaker/output
Test microphone
Test voice/TTS
Device/TTS status
```

Rules:

- persist device preferences locally per browser/device, not in the account/server profile;
- never sync a physical Desktop deviceId to Mobile;
- Video prejoin and Radio use the same local preferences;
- if output-device selection is unsupported, show an honest OS-managed output state instead of a fake selector;
- do not acquire a mic merely because Settings or Radio rendered;
- selecting a device may persist preference without opening the mic;
- acquisition is allowed only on an explicit user action such as Test Mic, prejoin/join, or Talk;
- once an explicit flow has a valid Group-owned local track, reuse it safely when compatible rather than creating a second translation mic owner.

### 4.9 Radio tap2 floor ordering

Correct lifecycle:

```text
TALKING
-> tap2
-> initiate recorder stop and retain Promise
-> disable local transmit track as appropriate
-> RELEASE FLOOR immediately
-> UI returns LISTENING / floor available
-> await transient local Blob
-> STT exactly once
-> translation variants
-> durable TEXT history
```

STT/translation/recorder Blob finalization must not hold the floor. Preserve idempotent floor release and Leave/device-lost safety.

### 4.10 Member-picker geometry

Desktop target:


Mobile target:

- use available visual viewport safely;
- member list must be substantially taller than the failed QA state;
- no large dead white region caused by content-height collapse;
- safe-area respected;
- Start Video remains reachable without layout traps;
- do not introduce fixed heights that break small landscape devices.
